01 · Current state

기능의 뼈대는 이미 있습니다

강아지와 장소 정책 구조, 4단계 배지, 홈 필터까지 구현돼 있습니다. 문제는 몸무게가 판정에 쓰이지 않고 장소 정책 데이터가 거의 없다는 점입니다.

🐶

강아지 프로필

크기·몸무게·가방·유모차·실내 매너 필드를 이미 보유합니다.

🏡

장소 정책

소·중·대형견, 실내·테라스, 가방·목줄·기저귀 필드가 존재합니다.

🚦

4단계 판정

바로 가능·조건부·확인 필요·어려움 배지와 필터가 있습니다.

현재 위험: 해당 크기 허용값이 비어 있어도 명시적 불가가 아니라는 이유로 ‘바로 가능’이 될 수 있습니다. 정책 상세가 7곳 수준이라 대형견에게 특히 신뢰하기 어렵습니다.
02 · Product principles

모르면 ‘가능’이 아니라 ‘확인 필요’

보수적 판정명시된 허용 근거가 있을 때만 바로 가능으로 승격합니다.
정확한 값 우선최대 허용 체중 → 크기 허용 → 일반 동반 가능 순으로 판단합니다.
이유 중심 UX조건부 한 단어 대신 테라스만·가방 필수처럼 이유를 표시합니다.
전체 결과 완전성로드된 일부가 아니라 활성 장소 전체를 서버에서 필터링합니다.

04 · Data model

새 필드는 최대 허용 체중 하나만

기존 정책 필드를 최대한 재사용하고, 실제 kg 제한을 담기 위한 nullable 필드만 추가합니다. 추정값으로 기존 데이터를 채우지 않습니다.

🔎

신뢰 근거

verified_source, verified_at, notes를 모든 보강 데이터에 기록

몸무게 자동 추천: 10kg 미만 소형, 10~25kg 미만 중형, 25kg 이상 대형. 추천값은 사용자가 수정할 수 있고 장소의 정확한 최대 체중을 가장 우선합니다.

08 · Verification

32kg 대형견 실제 시나리오까지 검증

  • 정책 미확인 대형견 장소는 바로 가능이 아니라 확인 필요
  • 26kg 강아지와 최대 25kg 장소는 어려움
  • 대형견 가능·실내 가능 명시 장소만 바로 가능
  • 테라스 전용은 목록·지도·상세 모두 조건부
  • 가방 필수와 가방 이용 불가 조합은 어려움
  • 필터를 바꾸고 취소하면 목록이 변하지 않음
  • 적용 시 DB 전체 기준 N곳과 페이지 결과 일치
  • npm test, TypeScript, Android release build 통과
실기기 3개 프로필: 32kg 대형견(가방 불가), 15kg 중형견, 8kg 소형견(가방 가능)으로 경계와 조건 조합을 확인합니다.
09 · Risks

UI보다 데이터가 더 큰 프로젝트입니다

정책 데이터 부족우선 지역 200곳을 조사하고 70% 커버리지 이후 맞춤 필터를 본격 노출합니다.
오래된 업장 정책출처·확인일을 표시하고 180일 경과 시 확인 필요로 낮춥니다.
몸무게 기준 예외자동 추천을 강제하지 않고 수동 수정과 장소 최대 체중을 우선합니다.
부분 페이지 필터RPC v2로 활성 장소 전체를 서버에서 필터링하고 정확한 count를 돌려줍니다.
대부분 확인 필요로 변화잘못된 바로 가능보다 안전을 우선하고 지역별 데이터 확보와 함께 단계적으로 활성화합니다.
dirty 워크트리변경 manifest와 범위별 diff를 만들고 승인 전에는 앱 배포를 하지 않습니다.
