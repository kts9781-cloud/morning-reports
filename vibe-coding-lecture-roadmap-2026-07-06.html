바이브코딩 강의 기획안

AI로 코드를 짜는 법보다,
서비스가 되게 만드는 구조를 가르치기

초보자와 1인 창업자가 실제로 막히는 지점은 프롬프트가 아니라 로그인, DB, API, 키 보안, 결제 검증, 배포 전 체크입니다.

추천 포지셔닝 “AI가 만든 앱을
실제 서비스로 바꾸는
최소 개발 상식”
왜 이 방향인가 핵심 개념 보안 구조 강의안 메시지

강의의 중심은 “에이전트”보다 “서비스 구조”가 좋습니다

스킬, 하네스 엔지니어링, 에이전트는 고급 주제로 좋지만, 초보 수강생에게 당장 필요한 것은 앱이 안전하게 돌아가는 기본 구조입니다.

흔한 바이브코딩 강의

프롬프트 → 화면 생성 → 끝

  • 예쁜 화면은 빨리 나오지만 실제 서비스 단계에서 막힘
  • API 키를 앱에 직접 넣는 보안 실수 발생
  • 로그인, DB 권한, 결제 검증, 배포 체크가 빠짐
추천하는 강의 방향

화면 → 백엔드 → API → 보안 → 출시

  • 프론트/백엔드/API/DB의 관계를 먼저 이해
  • 키를 어디에 보관하고 어떻게 호출해야 하는지 학습
  • AI가 짜준 코드를 사람이 검증하는 체크리스트 제공

수강생이 반드시 알아야 할 5가지 개념

이 다섯 가지를 이해하면 AI가 만든 코드를 무작정 붙여넣지 않고, 어디가 위험한지 판단할 수 있습니다.

01프론트엔드

사용자가 보는 화면. 앱/웹 UI와 입력 폼.

02백엔드

비밀키 보관, 권한 체크, 데이터 처리.

03DB

사용자, 결제, 기록, 결과가 저장되는 곳.

04API

프론트와 백엔드, 외부 서비스가 대화하는 약속.

05키 보안

public key와 secret key를 구분하는 능력.

대표님 경험이 강의의 차별점입니다

이론보다 “앱을 실제 출시하며 겪은 실수와 체크리스트”가 훨씬 강합니다.

실전성

AI가 화면은 만들지만 서비스는 구조가 만든다

로그인, DB, API, 결제, 배포까지 연결되어야 사용자가 실제로 쓸 수 있습니다.

현실 문제

초보자는 에러보다 보안에서 크게 사고 납니다

키 노출, RLS 누락, 결제 검증 부재처럼 출시 후 피해가 커지는 지점을 알려줘야 합니다.

차별화

프롬프트 강의가 아니라 서비스 완성 강의

“어떻게 물어볼까”보다 “무엇을 확인해야 할까”를 가르치는 강의가 됩니다.

보안 파트는 꼭 넣는 게 좋습니다

바이브코딩에서 가장 위험한 실수는 “작동한다”는 이유로 secret key를 앱 안에 넣는 것입니다.

나쁜 구조

앱 → OpenAI/Gemini API 직접 호출 → secret key가 앱에 포함됨

좋은 구조

앱 → Supabase Edge Function/백엔드 → AI API 호출 → secret key는 서버에만 보관

나쁜 구조

Supabase service role key를 프론트에 넣거나 RLS 없이 DB를 열어둠

좋은 구조

클라이언트는 anon key만 사용하고, RLS로 사용자별 접근 권한을 제한

추천 커리큘럼

처음부터 어려운 AI 에이전트 개념으로 가지 말고, 실제 앱이 완성되는 순서대로 구성합니다.

1

바이브코딩의 현실

화면은 빨리 만들 수 있지만, 실제 서비스는 로그인·DB·API·보안에서 막힌다는 점을 설명합니다.

2

앱의 기본 구조

프론트엔드, 백엔드, DB, API가 각각 무엇을 맡는지 그림으로 설명합니다.

3

API와 키 이해

OpenAI, Gemini, Supabase 같은 서비스에서 키를 발급받고, public/secret 차이를 배웁니다.

4

보안 사고 패턴

앱 안에 secret key 넣기, RLS 누락, 결제 검증 생략 등 대표 실수를 다룹니다.

5

안전한 연동 구조

앱 → 백엔드/Edge Function → 외부 API 구조로 키를 보호하는 방법을 실습합니다.

6

실제 예제 만들기

AI 상담 앱처럼 단순한 예제로 로그인, DB 저장, AI 호출, 결과 저장까지 연결합니다.

7

AI와 협업하는 법

요구사항을 구조적으로 주는 법, 에러 로그를 읽는 법, 보안 체크를 AI에게 요구하는 법을 알려줍니다.

8

출시 전 체크리스트

환경변수, 키 노출, DB 권한, 결제 검증, 개인정보, 로그, 앱스토어 심사 포인트를 확인합니다.

출시 전 체크리스트 예시

강의 말미에 수강생이 그대로 따라 할 수 있는 체크리스트를 제공하면 만족도가 높습니다.

✓AI API secret key가 앱 코드에 들어가 있지 않은가?
✓Supabase service role key가 프론트에 노출되지 않았는가?
✓DB 테이블에 RLS가 켜져 있고 사용자별 권한이 제한되는가?
✓결제 결과를 앱 화면만 믿지 않고 서버/웹훅에서 검증하는가?
✓로그에 개인정보나 API 응답 원문이 과도하게 남지 않는가?
✓앱스토어 심사에서 설명해야 할 데이터 수집/AI 기능이 정리되어 있는가?

강의 핵심 문장

“비개발자도 AI로 앱을 만들 수는 있습니다. 하지만 사용자가 실제로 쓰는 서비스로 내보내려면 프론트엔드, 백엔드, API, 키 보안의 최소 개념은 반드시 알아야 합니다.”

따라서 이 강의는 단순히 프롬프트를 잘 쓰는 수업이 아니라, AI가 만든 코드를 안전한 서비스 구조로 연결하는 수업으로 잡는 것이 좋습니다.
